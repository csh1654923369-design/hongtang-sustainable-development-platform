# 红塘村可持续发展平台

> 当前版本：V1.2。V1.0、V1.1均为只读本地快照，V1.2独立保存在自己的版本目录中，不调用旧版本源码或素材。

平台仍以一张全屏地图为首页，但V1.2不再把它理解成“把资料都放上地图”。用户先从一个生活问题进入，再沿地点、人物、线路、片区、时间和行动继续查看。2D地图、3D实景和地图编辑器读取同一套点、线、面及其属性；三者的区别只是观看和编辑方式，不是三套互不相干的数据。

首页左上角保留平台Logo、名称和“专题”入口，右上角保留2D／3D、影像图层和地图编辑入口。默认进入2D“航拍＋卫星”；切换2D／3D后，专题勾选、当前问题和观察尺度都会保留。老人或普通村民不需要理解GIS术语，只需先选择“小花园、茶产业、村里用水、塌方与安全、历史与文化”中的一件事。

## V1.2的核心变化

V1.2把平台从“空间对象查看器”推进为“理解红塘村怎样运转、哪里有问题、接下来怎样行动”的工具。

- 五个专题不再共用同一套展示话术。每个专题都有三个自己的问题视角：小花园关注位置、传播和变化；茶产业关注来源、流动和监测；村里用水关注全貌、供水和排水；塌方与安全关注隐患、影响和处置；历史与文化关注遗存、故事来源和延续。
- 专题问题同时连接五类人居关系：山水与生态环境、村民生活与地方知识、邻里协作与共同维护、住房院落与生产空间、水和道路等支撑网络。这些关系是解释框架，不是额外堆叠的五张地图。
- 每个专题可切换“全村、片区、家庭／地块、具体地点”等实际适用的观察尺度。切换尺度会改变页面给出的阅读提示，帮助用户避免只看一个孤立点位。
- 点开地点、线路或片区后，详情统一说明资料依据、当前进度、关联对象、观察尺度、维护或行动者、变化日期和下一步。待核实资料不会被包装成正式事实。
- 详情中的“补充或核实”会在新窗口直接定位到地图编辑器中的对应要素。编辑器新增“核实、关系与行动”表单，可修改证据状态、记录日期、关联对象、行动阶段、负责人和下一步。
- 编辑器仍采用安全的临时模式：点击“应用到平台”后，当前已打开的2D和3D立即看到修改；刷新页面恢复原始数据，不写入Supabase，也不覆盖本地素材。
- 水专题继续作为结构最完整的样板：节点、线路、供水片区、上下游和维护问题都可连续阅读。其他专题使用明确的“待核实资料”支持结构演示，后续必须用实地调查逐项替换或确认。

当前首页使用本版本“平台素材”中的手绘图、POI、149处村景照片坐标和586张素材照片。供水节点、线路和片区，以及茶产业、安全、历史专题中的补充点线面，均按页面状态区分“已有记录”和“待核实”，不能仅因出现在地图中就当作红塘现状事实。

## 启动方式

### 推荐：双击启动

在当前`V1.2`版本目录中双击：

```text
启动网站.bat
```

脚本会在后台启动开发服务器，并自动打开 <http://localhost:3000>。使用结束后双击 `关闭网站.bat`。如果网站已经启动，再次双击“启动网站”只会打开浏览器，不会重复启动服务。

### 终端启动

如果终端当前位于外层根目录，先进入源码文件夹：

```powershell
cd .\平台源码
npm install
npm run dev
```

浏览器访问 <http://localhost:3000> 或 <http://127.0.0.1:3000>。本地版与Vercel在线版都优先从同一个Supabase项目读取地点、供水专题、专题记录和现场照片；连接失败时自动回退到随网站打包的本地JSON和照片。网页公开读取需要配置 `NEXT_PUBLIC_SUPABASE_URL` 与 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`。2D云端底图还需要 `AMAP_WEB_KEY`；若使用新版高德Key，还应配置 `AMAP_SECURITY_JS_CODE`。3D首页需要可访问资产5139056的 `CESIUM_ION_TOKEN`。私密令牌和 `SUPABASE_SERVICE_KEY` 不得写入源码、网页或Git仓库。

`next.config.ts` 已关闭 Next.js 本地开发指示器，因此双击启动网站后，页面左下角不再显示黑色“N”按钮；该按钮原本仅属于开发工具，不是平台功能。

## 已实现的首页功能

- 首页由 HomeExperience 管理“3D实景 / 2D地图”切换；点击切换后先用约260毫秒完成右上角功能卡片的展开或收起，再替换并挂载目标地图，避免高德地图、航拍图层和点位初始化与界面动画争抢同一帧。过渡完成后仍只保留当前模式，减少显卡占用。
- 3D模式由 GaussianHome 与 public/cesium-viewer/index.html 加载红塘村高斯3D Tiles、世界地形、航空影像和本地无人机正射影像。
- 2D与3D共用 hongtang-real-map-features.json、hongtang-topic-records.json 和 hongtang-water-system.json。
- 当前基础地点包含56个POI和149处村景记录；2D与3D均以地图作为全屏底层，使用相同的分类筛选、矢量图钉、圆点、自动聚焦和锚定气泡详情。
- 2D地图使用高德 JavaScript API 2.0 提供道路、地名、水系和卫星遥感影像；右上角同一张功能卡片的下排分为“航拍／手绘”和“卫星／底图”两组，每组各自二选一且互不重置；首次打开首页默认显示“航拍＋卫星”。“底图”模式轻微降低饱和度和对比度，其余三种模式不受影响。按住左键可向任意方向拖动，滚轮缩放，点击右下角“回到中心”恢复村庄中心视图，也可点击“全屏查看”进入或退出浏览器全屏。地点图标使用独立于底图缩放的DOM矢量层，并按整数屏幕像素定位；悬停和选中不再整体缩放图标，避免浏览器把SVG临时栅格化而发糊。图钉和水专题对象的点击会短暂阻止底图空白点击，防止详情气泡刚打开就被关闭。
- 地点、线路、片区和两张本地影像的原始坐标保留为WGS84；进入高德2D显示层时统一转换为GCJ-02，避免云端底图与村庄资料整体错位。原始JSON不改动，3D继续读取WGS84坐标。
- 点击地点后，两种模式都会把视图移动并缩放到对应位置，再在点位旁显示气泡；点击供水线路或片区也会聚焦到空间对象，点击地图空白处或气泡关闭按钮会取消当前选择。普通地点采用相同造型与配色的矢量图钉，密集村景记录统一为圆点，地图标签只显示“村景记录”而不显示序号。
- “专题”由HomeExperience统一持有状态并只挂载一次。专题标题和具体列表合并在同一张大卡片中，通过“展开⌄ / 收起⌃”控制；展开或收起采用约260毫秒的高度缓动和轻微透明度过渡，文字与列表不位移、不缩放，避免回弹，也不再出现两张卡片之间的间隔。内容区直接显示五个专题，不重复显示“专题、全选、完成”标题行；公共服务和村景记录另列为“其他资料”。首次打开首页时五个专题从第一帧起默认全选；异步数据尚未读取完成时不显示“当前没有显示要素”等空状态，只有读取完成且筛选结果确实为空时才提示用户。每个专题均可勾选，也可点击“进入”切换到专题阅读状态；切换2D/3D不会重置当前专题或图层状态。
- V1.2的专题阅读状态由HomeExperience继续统一持有，并新增“当前问题”和“观察尺度”两项共享状态。因此从2D切换到3D，或从3D返回2D时，不仅图层勾选保持不变，正在回答的专题问题和“全村／片区／家庭地块／具体地点”尺度也不会跳回初始值。
- 进入任一专题后，左上角出现该专题自己的三个问题视角和关系链，并说明这个问题同时连接哪些人居关系。水专题的三个视角继续直接控制供排水数据显隐；其他专题通过不同问题组织同一批资料，不再只是换一种颜色或标题。
- 五个专题在2D和3D中分别使用固定专题色：小花园为绿色、茶产业为棕色、村里用水为蓝色、塌方与安全为砖红色、历史与文化为紫色。其他资料保留公共服务和村景记录原有颜色，并统一使用低遮挡圆点，不再显示大图钉；原“生态资源”测试点不再进入平台显示。
- 2D和3D右下角工具统一使用44像素深色圆角图标按钮、相同阴影和左侧悬停提示。2D保留“回到中心、全屏查看”；3D仅保留“操作设置、回到中心、全屏查看”，并将操作设置放在最上方。
- 小花园已接入35处位置资料，茶产业已有茶厂资料；茶园边界、采青联系、安全线索、古道和历史地点中的补充点线面均作为“待核实资料”显示。它们用于建立调查结构，不因出现在地图上就自动成为已核实事实。
- 进入“村里用水”后可打开“水系统全貌、饮水从哪来、排水到哪里”三个视角，沿着水源、线路、供水点、片区、沟渠、水塘和末端去向连续阅读。退出后恢复进入前的专题勾选状态。
- 水专题当前包含7个待核实节点、7条线路（3条待核实供水线路、4条依据手绘图蓝色水系校正的排水线路）和3个待核实供水片区；平台已有的2处污水设施点位也会保留在“水系统全貌”和“排水到哪里”中。手绘图仅用于校正自然主水系及东、西汇水支流，不用于推断地下供水管线；校正后的沟渠属性、季节性水量和实际流向仍需现场核实。点击任一节点、线路或片区后，2D与3D都会突出同一组上下游和服务关系；气泡中的关联对象可继续点击，地图会自动移动到新的对象。
- 3D中的供水片区采用基础不透明度0.31、随三维坐标、地形和相机视角实时同步的前景半透明覆盖层，最终显示在高斯模型画面上方，因此模型内外均连续可见，不会再被高斯点云、建筑或植被遮挡；点击片区仍会自动聚焦并显示原有详情气泡。片区保持专题蓝、清晰边界和选中/关联增强，供排水线路继续使用加粗、浅色描边和遮挡补偿。
- 水专题详情除空间位置外，还展示节点作用、片区用水对象、共同建设与维护事项，以及需要向村民继续了解的问题。它把平台用作梳理村庄关系的工具，而不是把尚未核实的路线当成事实。
- 五个专题的地点、线路和片区详情新增统一的“这条资料现在到哪一步”：显示资料依据、行动阶段、关联对象、观察尺度、维护或行动者、变化日期和下一步。点击“补充或核实”会在新窗口进入地图编辑页并定位到当前要素。
- 三维页面保留左键平移、右键围绕画面中心旋转、滚轮缩放、灵敏度设置、画质设置、回到中心和全屏功能。
- 固定页头、页脚和移动端底部导航均已移除；页面左上角悬浮显示平台Logo与名称，右上角用一张功能卡片容纳2D/3D切换、横向排列的两组2D图层按钮，以及最下方单独一行的“地图编辑 / 刷新后还原”入口。 手机端改为通栏纵向控制区：完整平台名称位于第一行，第二张通栏卡片把2D/3D与地图编辑并列在上排，航拍、手绘、卫星、底图位于下排；专题卡片与控制区等宽并紧接其下，避免左右分散和大面积遮挡地图。
- 已删除原地图页、记录页、村庄总览、六类事项独立路由及其专用页面组件。

## 3D高斯实景、无人机影像与原始素材

### 3D高斯实景首页

正式首页通过 `HomeExperience` 提供2D与3D双模式。进入首页时默认挂载2D地图，便于直接浏览且降低设备性能压力；切换到3D后，使用在线 Cesium 资源组合：红塘村高斯模型来自 Cesium ion 资产5139056，周边地形来自 Cesium World Terrain，背景来自Bing航空影像，村庄核心区继续叠加本地无人机正射影像。切换时先完成右上角按钮卡片约260毫秒的界面过渡，再挂载目标地图并卸载原地图；稳定状态下仍只有一种地图运行。平台通过以下文件完成接入：

```text
src/app/api/cesium-ion/asset/route.ts
src/components/home/HomeExperience.tsx
src/components/home/GaussianHome.tsx
src/components/map/MapExplorer.tsx
src/components/map/AmapVillageMap.tsx
src/app/api/amap-config/route.ts
src/app/_AMapService/[...segments]/route.ts
public/cesium-viewer/index.html
public/data/hongtang-orthophoto-0.3m.webp
public/data/hongtang-orthophoto.json
public/data/hongtang-real-map-features.json
```

`/api/cesium-ion/asset` 从服务端环境变量读取 `CESIUM_ION_TOKEN`，再把它作为Cesium ion公共访问令牌提供给3D查看器，用于请求模型资产5139056、世界地形资产1和Bing航空影像资产2。该令牌会参与浏览器端请求，因此应使用最小权限并通过Allowed URLs限制允许访问的平台域名；管理级私密令牌不得用于网页。部署或更换电脑时，需要在本地或Vercel环境变量中配置可用令牌；`.env.example` 只保留占位符，真实令牌不得提交到Git。

本地生成的核心DSM、周边SRTM高程网格、本地晕渲和本地Cesium三维瓦片仍保存在 `public/data` 与“平台素材”中，便于后续做离线方案、数据核对或对比测试；当前正式3D首页不再读取这些本地地形和模型文件。红塘村0.3米无人机正射影像仍作为核心区覆盖层使用。

点位数据由 `prepare-real-map-data.py` 生成。移除不再使用的生态资源类别后，POI按Excel记录保留55个地点；村景CSV按每个不同的实际坐标聚合照片，生成149处地点。最终二维与三维场景默认加载204个地点和586张照片的索引关系。坐标只要是有效WGS84经纬度就会进入三维场景，不按红塘村手绘图范围裁切；当前有4个村景坐标位于原二维手绘图范围外，它们在二维手绘图上自然隐藏，在三维地形中仍可看到。

二维和三维地点标记采用同一套视觉规则：56个POI使用清晰的SVG分类图钉，图钉中央绘制花朵、厂房、水滴、厕所、停车、学校、垃圾池、活动中心、村委会等对应矢量符号；149处密集村景记录使用小圆点；标题只在悬停或选中时显示，其中村景标签统一显示“村景记录”，不附加序号。点击地点后，两种模式都会自动移动并缩放视图。父页面从地点数据文件查找完整详情，复用 `MapDetailDrawer` 生成点位旁的气泡卡片；地图移动时持续更新气泡锚点。供水线路和片区沿用相同的点击聚焦与气泡逻辑。

查看器创建后立即使用无动画的固定视角定位红塘村中心（99.908740607°E，24.636255278°N），默认观察距离约1100米；模型和点位异步载入过程中不进入地球全览。查看器启用按需渲染，并提供“省电、均衡、清晰”三档画面质量；三档会同步调整页面分辨率倍率、在线3D Tiles屏幕误差、世界地形屏幕误差和雾效。左键水平平移、右键围绕画面中心旋转、滚轮固定比例缩放，中键停用；三个灵敏度滑块的显示范围均为0.3—2.0、步长0.1、默认1.0。成功状态不会常驻左下角；仅在加载过程或发生错误时显示必要提示。

原 SparkJS 2.1.0 轻量化成果和本地 Cesium 3D Tiles 没有删除。它们仍可用于离线预览、性能对比或未来的在线/本地混合加载，但当前正式首页使用 Cesium ion 在线模型、Cesium World Terrain和Bing航空影像。
### 真实手绘图、POI与村景照片

首页2D地图以高德在线地图为云端底层，并通过 `AMap.ImageLayer` 按地理范围叠加三农数据GeoServer的红塘村手绘图或本地无人机影像。地点、水系线路和管理片区继续叠加在同一地图中。网页运行文件为：

```text
public/data/hongtang-handdrawn-map.png
public/data/hongtang-map-layers.json
public/data/hongtang-real-map-features.json
src/components/map/AmapVillageMap.tsx
```

界面右上角使用一张功能卡片：上排切换2D/3D，选中2D后，下排横向分为左侧“航拍／手绘”和右侧“卫星／底图”两组。每组内部只能选一个，但两组可同时保留各自的选择，并且在水专题的“水系统全貌、饮水从哪来、排水到哪里”之间切换时保持不变：左组决定村庄覆盖层，右组决定其下方的云端底层；切换到3D时整行按钮自然收起，返回2D时自然展开，组件不会被重新创建。首次打开首页默认选择“航拍＋卫星”。“航拍”叠加红塘正射影像，“手绘”叠加村庄手绘成果；“卫星”使用高德官方卫星影像和路网，“底图”显示经过轻微淡化的高德在线道路和地名。两张村庄覆盖层设置透明度，村域外仍可继续看到并拖动高德地图。若高德脚本、网络或Key不可用，页面自动回退到原有本地影像地图，不影响地点筛选和详情查看。

真实点位运行文件由`../平台素材/POI_1785232551999.xlsx`、`../平台素材/poi图片.csv`和`../平台素材/村景图片.csv`生成；当前包含55个POI、149处村景照片坐标、392张POI照片和194张村景照片，共204个地点和586张照片。586张照片已下载并压缩为WebP，正式网页从Supabase Storage的`hongtang-photos`公开素材桶读取；地点、供水专题和专题记录存放在`platform_datasets`表中。本地归档保存在`../平台素材/现场照片/web`，网页备用副本保存在`public/local-photos`，原始网址保存在`../平台素材/现场照片/photo-source-manifest.json`中。更新素材后，在`平台源码`中运行：

```powershell
python scripts/prepare-real-map-data.py
npm run prepare:map-service-assets
python scripts/localize-point-photos.py
python scripts/upload-platform-data-to-supabase.py
```

照片本地化脚本会断点续传，最长边压缩到1600像素并转换为WebP。只有全部照片都处理成功后，脚本才会更新地点JSON和本地备用副本。上传脚本把照片写入`hongtang-photos`，并同步三套共享数据；运行时只通过环境变量临时提供`SUPABASE_URL`和`SUPABASE_SERVICE_KEY`，服务器密钥不得保存到文件或提交到Git。云端更新完成后，本地版与在线版会同时看到新数据，无需把193MB照片提交到GitHub。

原始表格和GeoServer下载文件始终保存在`平台素材`，不纳入源码Git仓库。生成到`public/data`的建筑文件已脱敏；真实POI运行文件只使用表格中的点位名称、分类、简介、坐标、图片网址和资料时间，不读取或新增联系方式。

### 无人机正射影像

首页2D与3D共同使用本地无人机正射影像：3D中影像覆盖在Cesium World Terrain与Bing航空影像之上；2D中影像作为可切换的地理配准覆盖层叠加在高德地图上。两种模式读取由0.3米重采样正射影像生成的WebP展示文件和配套元数据：

```text
public/data/hongtang-orthophoto-0.3m.webp
public/data/hongtang-orthophoto.json
```

影像坐标系为 `EPSG:32647`，网页展示文件约 3.7MB。外层根目录中的 `../平台素材/Production_1-tif/` 保存约 1.92GB 的 4厘米正射影像、约 2.56GB 的 DSM，以及裁剪和重采样成果；这些原始文件不进入源码仓库。需要从 0.3 米 TIF 重新生成网页文件时，在 `平台源码` 中运行：

```powershell
npm run prepare:orthophoto
```

地点和村景记录会按经纬度投影到影像范围，超出当前正射影像范围的点位自动隐藏。正式公开或把影像提交到GitHub前，还需要确认航拍成果、手绘图和现场照片的公开授权及敏感区域处理方式。

地图左上角专题面板分为：

- 专题：小花园、茶产业、村里用水、塌方与安全、历史与文化。
- 其他资料：公共服务、村景记录。
- 光伏不纳入当前专题；原光伏演示页面和数据不在当前首页显示。
- 公共空间与调研资料：公共服务设施、文化资源、调研照片、建筑、道路、水体。

真实POI、村景记录和对应照片由生成脚本统一读取，不再手工写入`src/data/mockData.ts`。后续新增或修订素材时，更新“平台素材”中的Excel/CSV后重新运行生成脚本；互动业务演示数据仍保留在`src/data/mockData.ts`。

## 红塘轻量地图数据编辑器

本地启动平台后，可点击首页右上角地图控制卡片最下方的“地图编辑 / 刷新后还原”入口，在新窗口进入编辑页；也可直接访问 `http://localhost:3000/map-editor`。编辑器由本项目自主实现，不依赖或内嵌外部通用GIS编辑程序。界面借鉴桌面GIS的稳定分区：左侧是“专题 → 图层 → 要素”的内容目录，中间左缘是顶部标有“工具栏”的固定竖向上下文工具区，地图位于中央，右侧只显示当前所选要素的专属字段；地图上方不再悬浮通用工具栏。

手机端使用“图层／属性”底部导航控制两侧抽屉，两张抽屉互斥，关闭后地图恢复完整触控；选择具体要素时自动打开属性抽屉。平板端属性面板覆盖在地图右侧，不再挤窄地图或改变底图视野。数据尚未读取完成时显示明确的载入状态，读取失败时提供重新载入入口，不再短暂显示误导性的“0层”。

编辑器先按小花园、茶产业、村里用水、塌方与安全、历史与文化分组，再展开到具体图层和单个要素。每个图层显示点、线或面图标、数量、显隐与新增入口。新建工具由当前图层决定：小花园和塌方与安全只有点；村里用水含节点、线路和分区；茶产业、历史与文化按各自需要组合点、线、面。右侧属性随图层变化，例如小花园只编辑位置点及其已有说明，安全点显示隐患类型、风险等级和处置状态，茶园显示经营农户、茶树品种与土壤监测。

点要素可以直接拖动位置，线和面选中后可拖动节点。编辑器顶部使用与Word相同语义的“撤回”和“恢复”箭头按钮，最多保留最近5步编辑历史；连续输入同一字段或一次完整拖动各算一步，新增、删除和属性修改也可以逐步撤回、恢复，没有可用历史时相应按钮自动置灰。每个要素除基本信息和专题字段外，还可编辑资料依据、观察尺度、记录日期、依据说明、关联对象、行动阶段、维护或行动者和下一步。点击“应用到平台”后，已打开的2D和3D会立即使用同一份临时数据。编辑页只读取平台现有公开数据，不调用Supabase写入接口，也不修改本地JSON或平台素材；刷新首页或编辑页后恢复原始数据。正式保存需要后续另做管理员登录、草稿表、数据校验和审核发布流程。

当前专题空间数据模型：

- 小花园：只保留已有小花园位置点，不设置线要素或面要素。
- 茶产业：茶厂点位、茶园与监测点、茶园范围、采青与收购联系。
- 村里用水：已有设施、水源与设施节点、供排水线路、供水分区。
- 塌方与安全：塌方、边坡、道路、排水和农房维护等隐患点，仅允许点要素。
- 历史与文化：历史地点与老树、茶马古道、传统聚落范围。
- `public/data/hongtang-topic-spatial-demo.json` 中保留18个专题结构资料，页面统一按“待核实资料”表达；35处小花园位置点与水专题继续沿用原平台数据。

相关文件：

- `src/app/map-editor/page.tsx`：轻量编辑器页面。
- `src/components/map-editor/MapDataEditor.tsx`：按专题、图层和几何类型组织的点线面查看、绘制、移动和上下文属性编辑。
- `src/lib/editorLayerCatalog.ts`：把五个专题整理成编辑器左侧的分类图层树。
- `src/lib/humanSettlement.ts`：五类人居关系、五专题问题链、尺度、资料依据和行动阶段的统一定义。
- `src/components/map/SettlementTopicNavigator.tsx` 与 `HumanSettlementDetail.tsx`：2D／3D共用的专题阅读和详情闭环组件。
- `src/lib/topicSpatialData.ts` 与 `public/data/hongtang-topic-spatial-demo.json`：茶产业、塌方与安全、历史与文化的图层定义、专属字段及18个待核实要素；小花园不从该文件读取线面资料。
- `src/lib/temporaryMapEdits.ts`：编辑页与已打开首页之间的临时同步，不进行持久化。
- `scripts/verify-map-editor.mjs`：验证编辑结果立即进入2D/3D、刷新恢复原始数据且没有数据库写请求。
- `scripts/verify-map-editor-v2.mjs`：验证五专题分类、竖向工具区、安全专题仅点、水专题点线面、右侧专属字段，以及390像素手机抽屉与768像素平板覆盖面板。
- `scripts/verify-topic-spatial-data.mjs`：验证七个专题图层、18个待核实要素、小花园无额外线面图层以及其他专题几何约束。
