# 红塘村三维地点图钉设计

## 1. 目标

在现有红塘村 3D 高斯实景首页中加入 5 个真正锚定在三维场景中的示例地点图钉，让用户能够像使用二维“村里一张图”一样辨认事项类型、选择地点并查看详情，同时保持现有旋转、右键水平平移、滚轮定比缩放和灵敏度设置不变。

第一版服务于界面与交互演示，不声称点位是真实地理位置。所有点位均显示“演示位置，待实地核实”。

## 2. 第一版范围

三维首页只展示下列 5 个现有二维地图点位：

| 点位 ID | 事项类型 | 图钉短标签 | 主色 | 三维局部偏移（东、北） |
| --- | --- | --- | --- | --- |
| `map-13` | 小花园 | 花 | `#4f8d55` | `-0.32, 0.18` |
| `map-14` | 茶场 | 茶 | `#71803a` | `-0.08, 0.32` |
| `map-15` | 茶厂 | 厂 | `#8b6b32` | `0.22, 0.18` |
| `map-16` | 村里用水 | 水 | `#3387a0` | `0.33, -0.14` |
| `map-17` | 光伏设施 | 光 | `#d6942b` | `-0.18, -0.28` |

局部偏移是相对模型包围球半径的无量纲比例，只用于选择分散、容易点击的初始演示位置。实现时允许在首次可视化检查中小幅调整上述数值，使图钉落在模型覆盖范围内；调整后的最终数值必须固定保存，刷新页面时不得重新随机生成。

第一版不包括：真实坐标校准、Supabase 写入、用户新增三维点位、事项筛选、点位聚合、路线导航、建筑级属性和安全隐患点位。

## 3. 用户界面与交互

### 3.1 图钉

- 图钉使用与二维“村里一张图”一致的事项颜色，并在图钉内部显示“花、茶、厂、水、光”之一。
- 图钉旁始终显示“小花园、茶场、茶厂、村里用水、光伏设施”短名称；完整地点标题在详情面板中显示。
- 图钉保持基本固定的屏幕可读尺寸，不随镜头距离无限放大或缩小。
- 未选中图钉使用常规尺寸；选中图钉放大并显示清晰描边。只高亮，不自动移动镜头。
- 图钉锚点稍高于模型表面，避免被高斯模型遮住或产生明显闪烁。

### 3.2 详情面板

- 点击图钉后，网页外层根据点位 ID 从现有 `mapFeatures` 中取得 `SpatialFeature`，复用二维地图的事项数据，不在三维查看器中复制说明文字。
- 桌面端详情面板从右侧打开；手机端在底部打开，最大高度不超过可视区的 55%。
- 面板显示演示数据标记、事项类型、状态、完整标题、简要介绍、地点概称、更新时间，以及“演示位置，待实地核实”。
- 面板提供“定位到此处”和“进入事项页面”两个主要操作。
- 点击“定位到此处”后，镜头平滑靠近并保持斜向俯视，不穿入模型；普通图钉选择不得改变镜头位置。
- “进入事项页面”按现有映射进入 `/garden`、`/tea-factory`、`/water` 或 `/solar`。
- 点击关闭按钮或按 `Esc` 关闭详情并取消图钉高亮。
- 打开详情时，三维查看器右上角工具组向左让出面板宽度，并自动关闭已展开的“操作设置”；关闭详情后恢复原位。

### 3.3 简化原则

第一版同时展示 5 个图钉，不增加事项筛选、图层树或复杂图例。短标签和稳定配色承担类型辨认任务。点位增加到需要避免遮挡时，再单独设计“地点图层”筛选。

## 4. 架构与组件边界

采用“Cesium 负责空间、React 负责业务详情”的混合结构：

1. `src/data/gaussianDemoPoints.ts` 保存 5 个点位 ID、短标签、颜色和固定局部偏移，不复制标题、状态和说明。
2. `GaussianHome` 从 `contentService.getMapFeatures()` 中选择 `map-13` 至 `map-17`，把渲染所需的最小数据发给同源 iframe。
3. `public/gaussian-viewer/index.html` 在模型就绪后将配置转换为 Cesium 实体，负责三维位置、图钉绘制、拾取、高亮和镜头定位。
4. iframe 只把选中的点位 ID 发回父页面；父页面查找现有 `SpatialFeature` 并显示详情。
5. `MapDetailDrawer` 增加可选的“定位到此处”回调和适合三维首页的显示变体。二维地图不传该回调，因此原有行为保持不变。

此边界保证业务数据只有一个来源，且未来把演示偏移替换为真实经纬度、高度时不需要重写详情界面。

## 5. 同源消息协议

父页面发送：

```ts
type GaussianPointPayload = {
  id: "map-13" | "map-14" | "map-15" | "map-16" | "map-17";
  categoryLabel: string;
  shortLabel: string;
  color: string;
  eastRatio: number;
  northRatio: number;
};

{ type: "hongtang-gaussian-points-set", points: GaussianPointPayload[] }
{ type: "hongtang-gaussian-point-focus", id: GaussianPointPayload["id"] }
{ type: "hongtang-gaussian-point-clear" }
{ type: "hongtang-gaussian-detail-state", open: boolean }
```

iframe 发送：

```ts
{ type: "hongtang-gaussian-points-ready", count: number }
{ type: "hongtang-gaussian-point-selected", id: GaussianPointPayload["id"] }
{ type: "hongtang-gaussian-points-error", detail: string }
```

双方都必须校验 `event.origin === window.location.origin`、消息类型和点位 ID。父页面重复发送同一批点位时，iframe 应更新或复用既有实体，不得重复创建。

## 6. 三维位置算法

模型加载完成后，以 `tileset.boundingSphere.center` 为基点：

1. 用 WGS84 椭球法线得到局部“上”方向。
2. 由地球 Z 轴和“上”方向叉乘得到局部“东”，再由“上”和“东”得到局部“北”。
3. 按表中 `eastRatio`、`northRatio` 与模型包围球半径计算平面目标位置。
4. 从目标位置上方沿局部“下”方向执行最详细射线拾取，优先取得高斯 3D Tiles 表面交点。
5. 在交点上沿局部“上”方向增加 `max(0.8 米, 包围球半径 × 0.004)` 的高度作为图钉锚点。
6. 如果射线没有取得交点，使用平面目标位置加 `包围球半径 × 0.06` 的备用高度，并将错误计入状态提示，但不阻止其他点位创建。

5 个锚点在当前会话中缓存。“定位到此处”使用缓存位置和模型半径计算镜头目标，飞行动画为 1.2 秒，结束距离为 `max(点位到模型中心距离 × 0.22, 包围球半径 × 0.12)`。

## 7. 状态与错误处理

- 父页面可以在模型就绪前发送点位；iframe 保存最后一批有效配置，在模型就绪后创建实体。
- 父页面在收到现有 `hongtang-gaussian-ready` 后再次发送点位，处理 iframe 较晚加载或重载的情况。
- 5 个实体全部创建后发送 `hongtang-gaussian-points-ready`。部分点位使用备用位置也计入数量。
- 点位消息无效时忽略该消息并发送简短错误；三维模型继续可用。
- 单点投射失败不影响其余点位。全部创建失败时，在现有状态区显示“地点暂时无法加载”，但不切换到模型加载失败页面。
- iframe 重载后父页面清除当前选择；不会显示与新场景不同步的旧详情。
- 点位文案以文本节点或 React 文本插值渲染，不接受 HTML 字符串。

## 8. 响应式与可用性

- 桌面端详情宽度为 340 至 380 像素，保留模型大部分可视面积。
- 详情打开时，右上工具组和操作设置面板向左避让；关闭详情后恢复。
- 390 像素宽度下详情使用底部抽屉，按钮保持可点击，页面不得横向溢出。
- 图钉短名称使用高对比白底深色文字，字号不低于 12 像素；详情正文沿用平台现有字号与颜色体系。
- 详情关闭按钮提供明确的中文 `aria-label`，`Esc` 与按钮执行相同行为。
- 三维 Canvas 仍以鼠标和触控点击为主要点位选择方式；详情内所有操作均可通过键盘访问。

## 9. 测试与验收

实施严格按测试先行：先扩展 `scripts/demo-smoke.mjs` 并观察预期失败，再编写生产代码。

自动化验收包括：

1. 模型就绪后收到且只收到 5 个点位，ID 为 `map-13` 至 `map-17`。
2. 5 个点位的类别、短标签和颜色与本设计一致。
3. 选择图钉后打开正确详情，显示类型、状态、标题和演示位置提示。
4. 选择图钉前后相机位置和方向保持在容差内，证明选择本身不触发镜头移动。
5. 点击“定位到此处”后相机与目标点距离减小，选中状态保持。
6. 切换图钉、关闭按钮和 `Esc` 都更新选中状态。
7. iframe 重载后点位恢复为 5 个，实体不会重复。
8. 390 像素视口使用底部详情且没有横向溢出。
9. 现有右键水平平移、滚轮定比缩放、两项灵敏度和 14 项演示流程继续通过。
10. `npm run lint`、`npm run typecheck`、`npm run build` 和 `git diff --check` 通过。

## 11. 完成标准

用户打开首页后可以看到 5 个稳定、可区分且锚定在模型上的示例图钉；点击任一图钉会显示与二维地图一致的地点详情但不移动镜头；只有点击“定位到此处”才平滑靠近；手机端可正常操作；所有演示位置均明确标注为待核实；现有模型操作与二维地图功能没有回归。
